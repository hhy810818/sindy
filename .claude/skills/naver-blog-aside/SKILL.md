# 네이버 블로그 × Aside 워크플로우

입력: 포스팅 폴더 경로 (예: `blog/2026-08-banksy-still-here/`) 또는 사진 파일 목록 + 메모.
출력: 폴더 안의 `원고.md`, 그리고 (Aside 사용 가능 시) 네이버 블로그 **임시저장** 글 1개.

## 0단계: 환경 확인

- Aside MCP 도구가 보이는지 확인한다 (로컬 Mac에서 `claude mcp add aside -- aside mcp`로 등록된 경우).
- **Aside가 없으면** (클라우드 세션, Linux/Windows, 앱이 꺼져 있음): 1·3·4단계의 Aside 작업은 건너뛰고,
  원고만 완성한 뒤 "Mac에서 Aside로 이어서 할 작업" 목록을 사용자에게 준다. 없는 도구를 흉내 내지 않는다.
- 사용자가 blog.naver.com에 로그인되어 있지 않으면 로그인은 사용자에게 맡긴다. 비밀번호를 묻거나 입력하지 않는다.

## 1단계: 소재 파악

1. 폴더의 사진을 모두 본다 (많으면 썸네일 컨택트시트로 묶어서 본다).
2. EXIF 촬영일시를 읽어 방문 날짜를 확정한다.
3. 티켓·안내판·간판 사진에서 장소명, 기간, 작품명 등 사실 정보를 읽어 낸다.
4. `메모.md`가 있으면 우선 적용한다. 가격, 동행, 소요 시간, 느낀 점은 **메모나 사진에 근거가 있을 때만** 쓴다.
   근거가 없는 개인 경험은 `⟦확인 필요: …⟧`로 남겨 사용자가 채우게 한다. 지어내지 않는다.

## 2단계: 리서치 (Aside 또는 웹 검색)

Aside가 있으면 로그인된 브라우저로 직접 확인한다:
- 네이버 검색 → 블로그 탭에서 메인 키워드 후보 2~3개 각각의 상위 5개 글: 제목 패턴, 글 길이, 사진 수, 다루는 항목
- 네이버 DataLab 검색어트렌드: 후보 키워드 최근 3개월 비교 → 메인 키워드 1개 선정
- 공식 정보(운영 시간, 가격, 기간, 위치)는 공식 페이지나 예매처에서 확인

Aside가 없으면 웹 검색으로 공식 정보만 확인하고, 키워드는 상위 노출 제목 패턴으로 추정한다.

## 3단계: 원고 작성

`naver-blog` 스킬의 규칙(제목 25~35자, 본문 1,500~3,000자, D.I.A. 체크리스트, 태그 20~30개, 최종 출력 형식)을 그대로 따른다.
추가 규칙:
- 사진 위치는 실제 파일명으로 표시한다: `[사진: 파일명.jpg | 캡션]`
- 사진은 글 흐름 순서대로 12~20장 고른다. 중복·흐린 사진·안내문 전문 사진은 빼거나 1장만 쓴다.
- 얼굴이 크게 나온 가족/아이 사진은 `(얼굴 노출 확인)` 표시를 붙여 사용자가 판단하게 한다.
- 결과를 `<폴더>/원고.md`로 저장한다.

## 4단계: 스마트에디터 입력 (Aside)

Aside에 다음 순서로 지시한다:
1. blog.naver.com → 글쓰기 열기
2. 제목 입력
3. 본문을 위에서부터 입력: 소제목은 '소제목' 서식, 목록·표는 에디터 기본 서식 사용
4. `[사진: 파일명 | 캡션]` 위치마다 폴더의 해당 파일을 업로드하고 캡션 입력
5. 카테고리 선택 (사용자가 지정한 것, 없으면 묻는다), 태그 입력
6. **임시저장** 클릭 → 저장 완료 확인
7. 발행 버튼은 누르지 않는다. 공개 설정·예약 발행도 건드리지 않는다.

## 5단계: 보고

사용자에게 다음을 짧게 알린다:
- 선정한 메인 키워드와 이유 (리서치 근거 1줄)
- `⟦확인 필요⟧` 항목 목록
- 임시저장 여부 (Aside를 못 썼다면 Mac에서 할 일 체크리스트)
- 발행 전 사용자가 볼 것: 사진 순서, 얼굴 노출, 사실관계

## 절대 규칙

- 발행·삭제·댓글 작성·이웃 추가 등 계정에 공개적으로 남는 행동은 하지 않는다.
- 하루에 여러 글을 연속 임시저장·발행하도록 돌리지 않는다 (어뷰징 패턴으로 오인될 수 있음).
- 방문하지 않은 곳, 쓰지 않은 제품의 경험을 지어내지 않는다.
